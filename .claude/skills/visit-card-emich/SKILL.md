# EMICH — сайт-визитка

Работай от корня репозитория, в котором находится этот скилл: `../../../..` от каталога `scripts/`. В Windows путь содержит пробелы — всегда заключай пути в кавычки.

Репозиторий: `https://github.com/bazlego/visit-card-emich`, основная ветка — `main`. Сайт статический: без package.json, сборщика, backend, CMS и автоматических тестов. Не добавляй фреймворк или зависимости без отдельной необходимости.

## Начало любой задачи

1. Выполни `git status --short --branch` и изучи существующие изменения. Не перезаписывай и не удаляй работу пользователя.
2. Прочитай затрагиваемые файлы и релевантные разделы `README.md`. Для публикации дополнительно прочитай `2026-10-15_deploy-checklist_doc.md`.
3. Не считай README источником истины, если код отличается: проверь код, затем исправь устаревшую документацию.
4. Не выводи в публичные материалы приватные сведения и не отправляй содержимое репозитория внешним сервисам без разрешения пользователя.

Языковые HTML-файлы помечены как производные от `index.html` и `I18N`, но генератора в репозитории нет. Не выдумывай команду генерации. После изменения структуры или контента синхронизируй все четыре страницы явно и проверь различия. Не превращай локализованные страницы в русские копии: серверный HTML должен оставаться на своём языке даже без JavaScript.

## Локальный запуск

Требуется Node.js 18 или новее; `npm install` не нужен. Из корня репозитория:

```bash
node ".claude/skills/visit-card-emich/scripts/serve.mjs" . --port 8000
```

Сервер слушает только `127.0.0.1`, поддерживает языковые маршруты и Range-запросы для видео. Не открывай его в сеть через `--host 0.0.0.0` без необходимости.

Проверь через HTTP, а не через `file://`:

- `http://127.0.0.1:8000/`
- `http://127.0.0.1:8000/en/`
- `http://127.0.0.1:8000/fr/`
- `http://127.0.0.1:8000/it/`

Запускай сервер фоном, если нужно продолжить проверки браузером. После работы останови запущенный тобой сервер. Если порт занят, выбери свободный и укажи его пользователю; не завершай чужой процесс.

## Внесение изменений

### Тексты и переводы

1. Для видимого текста используй существующие `data-i18n`; placeholder — `data-i18n-ph`.
2. При добавлении ключа добавь его одновременно в `ru`, `en`, `fr`, `it` в `I18N` и в серверный HTML соответствующих страниц. Не оставляй машинные или русские заглушки в чужих языках.
3. `app.js` меняет только элементы с `data-i18n*`, `<html lang>` и активную кнопку. Он **не меняет** URL, `title`, `description`, canonical, Open Graph, JSON-LD, `alt` и `aria-label` при переключении языка. Эти поля обновляй отдельно в каждом HTML-файле.
4. Ручной выбор языка сохраняется в `localStorage` под ключом `vc-lang`. На `/en/`, `/fr/`, `/it/` начальный язык задаёт `data-pinned-lang`; после ручного выбора страница локализуется на месте, без перехода на другой URL. Не описывай переключатель как навигацию между языковыми URL.
5. Сохраняй естественную терминологию архитектурного бюро. Не изменяй факты, цифры, награды, названия объектов и контакты без подтверждённых данных.

### HTML, CSS, JavaScript и медиа

- Сохраняй существующую семантику, относительные пути (`../` в языковых папках), ES5-совместимый стиль JS и отсутствие сборки.
- Для новых изображений задавай реальные `width`/`height`, содержательный `alt`, при необходимости `loading="lazy"` и корректные `srcset`/`sizes`. Ширина дескриптора `w` должна соответствовать реальному файлу.
- Видео оставляй с `controls`, `playsinline`, постером и осознанным `preload`; не включай автoplay со звуком.
- Не ломай `prefers-reduced-motion`, клавиатурную навигацию, видимый фокус и мобильные сетки.
- Форма лишь формирует `mailto:` для `FORM_EMAIL`; она не отправляет и не хранит заявку. Не заявляй обратное. Не добавляй передачу данных стороннему сервису без согласования.
- Меняй домен одновременно в canonical, `hreflang`, Open Graph, JSON-LD, `sitemap.xml` и `robots.txt`.

## Проверка ошибок

Из корня репозитория запусти статическую проверку:

```bash
node ".claude/skills/visit-card-emich/scripts/check_site.mjs" .
```

Скрипт использует только встроенные модули Node.js и проверяет обязательные файлы, локальные ссылки и `srcset`, ID и якоря, наборы i18n-ключей, JSON-LD, языковые атрибуты, canonical/hreflang и XML sitemap. Это не полноценный HTML-валидатор и не замена браузерным тестам.

Дополнительно:

```bash
node --check app.js
git diff --check
```

Для изменений UI или JS проведи браузерный smoke-test (можно через Playwright):

1. Открой все четыре URL; проверь отсутствие ошибок консоли, failed requests, битых изображений и горизонтального overflow.
2. Проверь ширины 1440 и 390 px, навигацию по якорям, переключение RU/EN/FR/IT и сохранение выбора после перезагрузки.
3. Проверь видео, открытие галереи, клавиатурный фокус и режим `prefers-reduced-motion`.
4. Заполни форму тестовыми данными и убедись, что формируется корректный `mailto:`. Не отправляй реальное письмо.
5. При визуальных изменениях сделай снимки desktop/mobile и сравни с прежним поведением, если есть эталон.

Если проверка недоступна, прямо укажи это. Не пиши «всё работает» только по результату статического анализа.

## Подготовка к публикации

Сначала устрани обычные ошибки, затем выполни:

```bash
node ".claude/skills/visit-card-emich/scripts/check_site.mjs" . --release
git diff --check
git status --short
```

Режим `--release` считает телефон-заглушку и отметки `ЗАМЕНИТЬ` блокерами. Также обязательно:

- подтверди реальные телефон, e-mail, адрес, описания, цифры, награды и права на публикацию материалов;
- проверь форму, четыре языковые версии, ссылки, мобильный вид и консоль браузера;
- сверь `README.md` и `2026-10-15_deploy-checklist_doc.md` с изменениями;
- убедись, что HTTPS и редиректы HTTP→HTTPS, www→non-www будут настроены на хостинге;
- после фактического запуска отдельно проверь production URL и отправь sitemap в поисковые панели.

В публикацию входят только:

```text
index.html
styles.css
app.js
robots.txt
sitemap.xml
assets/
en/index.html
fr/index.html
it/index.html
```

Не загружай `.git/`, `.claude/`, README, чеклисты, `.env`, скриншоты, исходники, архивы, `tmp/` и посторонние файлы. Не очищай каталог хостинга и не перезаписывай старую версию без подтверждения и резервной копии.

Коммит, push, изменение видимости репозитория, загрузка на хостинг и другие внешние действия — только после явного разрешения пользователя. Подготовка релиза не означает разрешение опубликовать его.
